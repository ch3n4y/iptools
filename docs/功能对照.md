# 功能对照：原版《IP 地址修改器》5.0.5.8 → 本项目

对照依据：kn007 官方发布页（<https://kn007.net/topics/ip-address-modifier-5-0-remastered/>）的功能说明与
5.0.x 更新历史中列出的功能点。原版为 AutoIt 编写的单文件工具，本项目为 Tauri 2 + Rust + React 的全新实现，
**不使用原版代码、资源或配置格式**。

图例：✅ 已实现并验证 ｜ 🟡 已实现但交互方式不同 ｜ ➖ 有意不实现（含原因）

## 1. 网卡管理

| 原版功能 | 本项目 | 状态 |
| --- | --- | --- |
| 网卡列表：名称、MAC、系统序号 | `net::adapters`（`GetAdaptersAddresses` + `GetIfEntry2`）返回名称、描述、MAC、永久 MAC、序号、MTU、链路速度、媒体类型 | ✅ |
| 网卡状态图标（已连接 / 网线未连接 / 已禁用 / 网卡故障） | `AdapterStatus`：`connected / disconnected / disabled / faulty / unknown`，由 `OperStatus` + `MediaConnectState` + 设备 `ConfigFlags` 推导 | ✅ |
| 优先显示「已连接」网卡（有网关、系统序号靠前优先） | 列表排序：已连接 → 有默认网关 → IfIndex；首次进入默认选中该网卡 | ✅ |
| 刷新列表 / 刷新当前配置（后合并为一个操作） | 标题栏「刷新」按钮 + 可配置自动轮询（窗口隐藏时暂停）+ 窗口重新可见时刷新 | ✅ |
| 网卡启用 / 禁用（原版用 Setupapi.dll，报错时提示提升权限） | `SetupAPI`：`SetupDiSetClassInstallParamsW(DIF_PROPERTYCHANGE)` + `SetupDiCallClassInstaller`，全局与每配置两段式，与原版同样的失败提示（需管理员） | ✅ |
| 接口跃点数修改 | `GetIpInterfaceEntry` / `SetIpInterfaceEntry`（关闭自动跃点并写入指定值），读回校验 | ✅ |
| MAC 地址修改（写注册表，原版位于网卡驱动键） | 写 `…\Class\{4d36e972-…}\NNNN\NetworkAddress` 并按需重启设备使其立即生效 | ✅ |
| 随机生成 MAC（第一字节最低位为偶数以符合单播） | `net::random_mac()` 保留本地管理位、清除组播位 | ✅ |
| MAC 合法性检测（5.0.6.10 起加强） | 12 位十六进制、非全 0 / 全 FF、组播位不得置位，错误文案给出规则 | ✅ |
| 计算机名 / 工作组修改（Netapi32） | `SetComputerNameExW`（DNS 主机名 + NetBIOS）+ `NetJoinDomain`（工作组）；名称规则校验与「需重启生效」提示 | ✅ |
| 检测到新硬件自动刷新（5.0.5.1，实验性） | 定时轮询 + 可见性事件刷新；未做 WMI 硬件事件订阅 | 🟡 |
| WMI 出错时可选择关闭 / 重启 / 忽略 | 本项目改用 Win32 API（不依赖 WMI），错误以稳定错误码 + 详情呈现，可重试 | 🟡 |

## 2. IP 配置

| 原版功能 | 本项目 | 状态 |
| --- | --- | --- |
| 静态 IP / 子网掩码 / 默认网关 / 主备 DNS 修改 | `ApplyRequest` → `write::apply`：netsh（无 shell、按适配器名传参）→ 读回校验 → 失败回滚 | ✅ |
| 静态 ←→ 自动获取（DHCP）切换 | `source=static` / `source=dhcp`，切换前清理残留的手动地址，避免原版出现过的「IP 与掩码缺失」问题 | ✅ |
| 单网卡多 IP | `addresses[]` 多地址（界面建议 ≤6），主地址带网关，附加地址单独添加 | ✅ |
| IP / 掩码组合有效性判断（不能设为网络地址或广播地址） | `subnet::validate`：网络/广播地址、回环、组播、掩码连续性、重复填写 | ✅ |
| IP 是否被其他网卡占用检测（5.0.3.4） | 写入前扫描其他网卡的地址集合并给出占用者名称 | ✅ |
| 子网掩码标签双击切换常用 A/B/C 类掩码（5.0.5.8） | 双击「子网掩码」标签按 IP 首字节套用 /8 /16 /24 | ✅ |
| 默认网关标签双击按 IP 子网自动生成网关（5.0.5.8） | 双击「默认网关」标签或点「按子网推导」按钮（网络地址 +1；若与主机地址冲突则 +2） | ✅ |
| 网关与掩码对 IP 的校验（5.0.5.6） | 网关不在任何已配置子网内 → 告警；网关与主机地址相同 → 错误 | ✅ |

## 7. 技术实现差异（供排查参考）

| 原版 | 本项目 |
| --- | --- |
| WMI（`Win32_NetworkAdapter(Configuration)`）、`Netapi32.dll`、`Setupapi.dll`、注册表 | `GetAdaptersAddresses` / `GetIfEntry2` / `GetIpInterfaceEntry` / `SendARP` / `IcmpSendEcho` / SetupAPI / `SetComputerNameExW` / `NetJoinDomain` + 注册表（用 `winreg`）；写入经 `netsh`（无 shell 调用，按适配器别名传参，规避本地化差异） |
| AutoIt 单文件脚本 | Rust 后端 + React 前端；配置为 JSON；错误为稳定错误码 |
| 读写配置在程序目录 | 默认 `%APPDATA%`，可选便携模式 |
| 无自动化测试 | Rust 29 项单测（子网计算、配置校验、方案迁移、CSV/Excel 解析、群 Ping 聚合、网卡规则）+ 前端 Vitest |

## 8. 平台行为说明（实测于 Windows 10 21H2 / Intel Wi-Fi 6 AX201）

这些是实现时按真实系统行为做的取舍，排查现象时可参考：

| 现象 | 原因与处理 |
| --- | --- |
| Wi-Fi 网卡上配置静态地址后，注册表 `EnableDHCP` 仍为 `1` | Windows 10 起部分适配器（尤其 Wi-Fi 配置文件）支持 DHCP 与静态地址共存。本程序因此以**是否存在手动地址**判定「静态/自动」，而不是只看 `EnableDHCP`；判定结果与用户预期一致，读回校验也按此语义进行。 |
| 切回自动获取时提示「DHCP 已在此接口上启用」 | 上一条的同一机制会让 `netsh ... source=dhcp` 返回非零。程序把该提示视为成功，并**显式删除残留的手动地址与旧默认路由**（`netsh interface ipv4 delete route`），避免旧网关一直显示。 |
| 接口跃点数此前写入失败 | `SetIpInterfaceEntry` 在该 Wi-Fi 网卡上返回失败，改为 `netsh interface ipv4 set interface ... metric=`（含 `metric=automatic` 恢复自动）；表单为空即表示「回到自动」。 |
| 「禁用」网卡后会从网卡列表中消失 | `GetAdaptersAddresses` 不返回被禁用的适配器。程序会用 SetupAPI + 注册表（连接别名、驱动描述、`CM_Get_DevNode_Status` 判定禁用）**补回被禁用的网卡**，状态显示「已禁用」，因此可以再次启用。 |
| 启用/禁用偶尔第一次无效 | 设备状态切换使用 `pnputil /disable-device|/enable-device`（对 Intel Wi-Fi 有效；`DIF_PROPERTYCHANGE` 在其类安装程序上返回 `ERROR_INVALID_USER_BUFFER`），并改为**轮询等待期望状态**（最长约 12 秒）。 |
| 修改 MAC 后有效地址未变化 | 多数驱动需要重建设备栈才能重新读取 `NetworkAddress`。程序先做软禁用/启用，若有效 MAC 仍未变化则用 `pnputil /restart-device` 强制重启设备（实测生效），并轮询等待网卡重新出现。 |
| 随机 MAC 与永久 MAC 不同 | Windows 的「随机硬件地址」功能会为 Wi-Fi 生成随机 MAC；`永久 MAC` 显示驱动报告的硬件地址，二者不同属正常。 |
| 安装包在 GitHub 上显示为 `IP._1.0.0_x64-setup.exe` | GitHub 会清洗资产名中的非 ASCII 字符；安装后程序与开始菜单仍为中文名「IP地址修改器」。 |
| 配置目录 | `%APPDATA%\iptools`（`settings.json`、`schemes.json`）；便携模式下为程序所在目录。 |
