# 消融记录（v1.0.4）

本文记录「删除不必要的功能、优化使用体验」这一轮改动的判断依据、删除清单、量化结果与复核结论。

## 1. 为什么做

第一轮实现的目标是「功能对标原版」，结果是把原版的能力面整个铺了出来：8 个导航页、43 个后端命令、11 个 CLI 子命令。
真正使用时暴露出三类浪费：

1. **入口重叠**：「高级选项」页能做的事，「网卡配置」页基本都能做（多 IP、自动网关、A/B/C 类默认掩码、写入前校验、备份、网卡启停），用户要在两个页面之间选一个来改同一个东西。
2. **参数无效**：个别参数在本机真实网卡上没有可观测效果，留着只会让人误以为「调了就有用」。
3. **死入口**：能力有，但既没有界面入口也不在 CLI 里，等于只有作者知道它存在。

所以这轮做的是**消融（ablation）**：以「能力重叠 + 实际可达性」为依据删掉冗余入口与无效参数。删的是入口和死代码，不是把有用的能力砍掉——凡是删掉的界面能力，都先确认它在别处仍然可用。

## 2. 判断依据（不是凭感觉删）

| 依据 | 做法 |
| --- | --- |
| 能力矩阵 | 把每个页面的输入项与后端命令一一对齐，标出重复项，重叠度高的页面才合并/删除 |
| 可达性 | 每个 CLI 子命令与 Tauri 命令逐条找调用者；既无界面入口又不在 CLI 的，按死代码处理 |
| 平台实测 | 在本机真实网卡（Intel Wi-Fi 6 AX201 / Intel I219-V）上验证参数是否真的改变系统行为 |
| 独立复核 | 改动后由只读审查逐文件核对悬空引用、命令/类型/文档一致性，再按结论二次清理 |

## 3. 删除清单

| 项目 | 处理 | 理由 |
| --- | --- | --- |
| 「高级选项」页（1011 行） | 整页删除 | 能力与「网卡配置」页完全重叠，只是多一层入口 |
| 「主机设置」页（752 行） | 整页删除 | MAC 修改迁入「网卡配置」页的「网卡 MAC 地址」卡片；只读诊断进「技术详情」折叠卡 |
| 计算机名 / 工作组（域）修改 | 能力整体删除（命令 −2） | 与「改 IP 工具」的主职责无关，且改错会影响登录域，风险大于收益 |
| `gatewayMetric`（网关接口跃点）字段 | 删除 | 与网卡级「接口跃点」重复，两个地方都能改跃点只会互相打架 |
| 群扫描 `retries`（重试次数）参数 | 删除 | 与超时、轮次两个参数职责重叠，实测调不出可区分的效果 |
| `--dump-devices` CLI | 删除（CLI 子命令 11 → 10） | 输出内容已被 `--dump-adapters` 覆盖 |
| `diagnose()` 命令 | 删除 | 只读诊断信息已在 `get_adapter` 的原始字段里，单列一个命令没有额外价值 |
| `set_portable_mode` 命令 | 删除 | 便携模式改为自动识别可执行文件同目录的 `portable.txt`，不需要界面开关 |
| `driver_value()`（`net/device.rs`） | 删除 | 空壳死函数（函数体恒返回 `None`），只为压住未使用导入告警而存在 |
| `validateComputerName` / `validateWorkgroupName` 及 2 个测试 | 删除 | 随「计算机名/工作组」能力一起消失的孤儿校验 |
| 全局快捷键（F1/F2/F5/F6/F8/F12 及角标） | 全部删除 | 与 Windows 自身及各输入法冲突概率高，且按钮都在一屏内可见 |

## 4. 明确保留的能力（避免误读为「功能缺失」）

多 IP 地址（最多 4 个）、掩码两种写法（`255.255.255.0` 与 `/24`）、网关按子网推导、DNS 手动/自动、接口跃点、网卡启用/禁用、MAC 修改与清除、方案管理（双击即应用）与 CSV / Excel / JSON 导入导出、ARP / ICMP / 系统 ping 三种群扫描、子网掩码与主机范围计算、完整 CLI 与自检。

## 5. 顺带的体验改进

1. **导航 8 页 → 5 页**：网卡配置 / 方案管理 / 工具箱 / 偏好设置 / 使用帮助，扁平一层、不再有二级认知负担。
2. **工具箱合并为一页**：网络扫描与掩码计算用 Segmented 切换，两个工具页同时挂载，来回切换不丢已展开的目标与扫描结果；掩码算完可以一键「用该网段扫描」。
3. **「用该网段扫描」的交接重做**：原先靠 `window` 自定义事件 + 80 ms 延时传递网段，合并成一个页面后事件必然早于扫描页挂载而丢失（提示成功但目标框仍是默认网段）。现改为经 store 传递、扫描页消费一次，任何挂载顺序都正确。
4. **首页卡片顺序按操作频率重排**：网卡列表 → 选中网卡详情 → **IP 配置** → 网卡 MAC 地址 → 备份与恢复 → 技术详情。主操作在前，低频且影响较大的 MAC 修改移到其后。
5. **偏好设置 8 张卡 → 6 张卡**，同类项合并。
6. **帮助页新增「已移除的功能」**：明确告知用户哪些能力没有了、对应能力现在在哪里，避免按老教程找不到入口。

## 6. 量化结果

| 指标 | 消融前 | 现在 |
| --- | --- | --- |
| 导航页 | 8 | 5 |
| Tauri 命令（`invoke_handler`） | 43 | 40 |
| CLI 子命令（`HEADLESS_FLAGS`） | 11 | 10 |
| `src/features/` 代码行数 | 7363 | 5812（−21%） |
| 前端主包 | 1283.77 kB（gzip 396.72 kB） | 1242.27 kB（gzip 386.75 kB） |
| 测试 | Rust 37 / 前端 37 | Rust 37 / 前端 35（−2 项针对已删功能的测试） |

## 7. 复核结论

- **命令面 1:1**：40 个 Tauri 命令 ↔ 40 个前端封装，没有前端调用已删除命令，也没有后端命令没有解封装。
- **无悬空引用**：`scan-spec`、`setPortableMode`、`set_portable_mode`、`driver_value`、`identity/validation`、`validateComputerName`、`validateWorkgroupName`、`--dump-devices`、`gatewayMetric`、`diagnose` 在 `src/` 与 `src-tauri/src/` 中均已无引用。
- **路由自洽**：`ViewKey` / `VIEW_META` / `VIEW_ORDER` / `VIEWS` 四处都是同样 5 个 key，默认页 `home` 存在，被删页面文件不在仓库中，也没有指向已删页面的跳转。
- **文档同步**：README、`docs/CONTRACT.md`、`docs/功能对照.md`、安装包 `longDescription`、提权提示、帮助页文案全部改为消融后的现状。
- **构建与测试**：`pnpm build`、`pnpm test`（35）、`cargo test`（37）、`cargo check --all-targets`（零告警）全部通过。

## 8. 尚未做的事（可选增强）
